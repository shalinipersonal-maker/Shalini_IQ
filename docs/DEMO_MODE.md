# Demo mode

ENTRAIQ ships demo-first so it can be presented before real integrations exist. Demo mode is the
default and requires no external credentials.

## How it is enabled

- Controlled by `NEXT_PUBLIC_DEMO_MODE`. Demo mode is **on** unless it is set to exactly `"false"`
  (`src/config/brand.ts`). With no env file, the app is in demo mode.
- `GET /api/health` reports `{ "mode": "demo" }` when demo mode is on.

## What the demo contains

Generated by `src/lib/demo/generate.ts` from a seeded catalogue (`src/lib/demo/catalog.ts`):

- **3 demo clients** (switchable from the topbar).
- **Amazon and Flipkart** marketplace data; a third marketplace slot shown as *Coming soon*.
- **Meta advertising** data plus Amazon Ads and Flipkart Ads.
- **12+ products**, **8+ advertising campaigns** across the three ad platforms, each with ad
  sets/ads and daily metrics.
- **90 days** of daily sales and advertising metrics (date ranges of 7/14/30/90 days and MTD all
  slice this).
- Inventory records, AI recommendations, recent activity, and creative templates.

## Internal consistency

All figures reconcile. Verify any time with:

```bash
npm run verify:data
```

It asserts: marketplace revenue sums to the total; product revenue sums to the total; campaign
spend sums to total spend; ROAS/ACOS/TACOS follow their definitions; per-platform attributed sales
stay a sensible share of sales (never summed into "unique" revenue); and there are ≥12 products and
≥8 campaigns.

## The demo indicator

Every screen shows a visible demo badge and the notice **"Sample data — not connected to live
marketplace accounts."** (`DEMO_NOTICE` in `src/config/brand.ts`). No simulated value is ever
labelled real-time, and no live connection is ever claimed (see
[`API_INTEGRATIONS.md`](API_INTEGRATIONS.md)).

## Interactions that work against local demo state

Entry (name gate) · change date range · change marketplace · switch client · search products ·
filter campaigns · open campaign / ad set / individual ad · create / edit / pause / resume a
campaign · generate AI insights, explain an insight, mark reviewed · open and export reports
(CSV + PDF of the data actually shown) · create / edit / save / reopen a creative, export PNG/JPEG ·
switch theme · navigate every module.

State is persisted to `localStorage` under `entraiq-demo-v1`, so demo changes (paused campaigns,
saved creatives, theme, brand name, reviewed insights) survive a page refresh. User actions are
recorded in an in-app **audit log** (Settings).

## Reset

**Settings → Reset Demo Data** clears all local overlays (campaign edits, creatives, reviewed
insights, uploads, audit entries) and returns the workspace to the freshly-generated baseline.
This only clears local demo state; it never contacts an external service.

## Roles in the demo

Switchable role (Agency Admin / Account Manager / Analyst / Client Viewer) gates actions via RBAC
(`src/lib/store.ts`). For example, Client Viewer cannot create or edit campaigns — the controls are
disabled, demonstrating permissions without a login backend.
